The Boot Process

What actually happens between pressing the power button and your OS running. Every layer, no hand-waving.

Power-On: The First Instruction

The moment power is applied, the CPU is in a known, hard-wired state. On x86, the instruction pointer CS:IP is set to 0xFFFF:0x0000, which in 16-bit real mode resolves to physical address 0xFFFF0. That's 16 bytes below the top of the first megabyte of address space.

At that address sits a JMP instruction — placed there by your motherboard firmware (BIOS or UEFI). It jumps to the actual firmware code, typically somewhere in the high flash ROM. The CPU has no idea what OS you're running. It doesn't care. It just executes the instruction at that address.

Why 0xFFFF0? After a reset, the CPU drives CS to 0xF000 with an internal base of 0xFFFF0000 (in 80386+). The real mode segment:offset pair 0xFFFF:0x0000 evaluates to 0xFFFF0. The first instructions are in ROM — ROM that exists at the top of the 1MB + a bit of extended space.

POST (Power-On Self Test)

Before anything useful happens, the BIOS runs POST. It's not magic — it's just a checklist:

  • Test CPU registers and basic instruction execution
  • Verify CMOS checksum (BIOS settings stored in battery-backed SRAM)
  • Initialize the memory controller and test RAM (that memory count you used to watch tick up)
  • Initialize buses: PCI, PCIe, USB
  • Enumerate and initialize hardware: IDE, SATA, NVMe controllers
  • Set up the Interrupt Vector Table (IVT) at address 0x0000

The Boot Device Search

After POST, the BIOS checks its configured boot order. It looks for a bootable device. For a disk, "bootable" is brutally simple: read the first 512 bytes. If the last two bytes are 0x55 and 0xAA — it's bootable. That's it. That's the entire check.

The 0x55AA signature is at bytes 510 and 511 (0-indexed), i.e., the last two bytes of the 512-byte sector. The BIOS loads those 512 bytes to address 0x7C00 and jumps to it. Your bootloader now has control.

Why 0x7C00?

The BIOS loads your MBR to physical address 0x7C00. Why this specific address? Historical accident. On the IBM PC (8088, 1981), this was the highest point where a 512-byte bootloader could live without overwriting itself or the BIOS data area, while still leaving the first 32KB for the OS. The original PC had 32KB of usable RAM. 0x7C00 = 0x8000 - 0x0200 (512 bytes).

The Full Boot Sequence

1
CPU Reset
CPU sets CS:IP = 0xFFFF:0x0000. All registers zeroed or set to known state. Cache flushed.
2
BIOS/Firmware executes
JMP at 0xFFFF0 takes us to firmware. POST runs, hardware initialized, IVT populated at 0x0000.
3
Boot device selected
First 512 bytes of boot device read. 0x55AA signature verified.
4
MBR loaded to 0x7C00
BIOS does JMP 0x0000:0x7C00. We're in 16-bit real mode. CPU hands off to your code.
5
Stage 1 Bootloader
MBR code (≤446 bytes usable) loads a larger Stage 2 from disk. Stage 2 has room to breathe.
6
Stage 2: The real work
Enable A20. Set up GDT. Switch to protected mode. Build page tables. Enter long mode.
7
Kernel entry
Parse ELF. Load segments. Pass boot information (memory map). Jump to kernel's entry point.
